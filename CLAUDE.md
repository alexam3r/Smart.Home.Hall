## Claude Code

Проектные правила, архитектура, MQTT-контракт и workflow — в `AGENTS.md` (импортирован выше). Этот файл добавляет только то, что специфично для Claude Code.

- Источник требований — `PRD.md`. Эталон поведения — `docs/main.cpp`. Не меняй топики, пины, тайминги и порядок ключей JSON.
- Работай по блокам из PRD §5. Не пиши весь рефакторинг сразу: после каждого блока — `pio run`, обновление графа graphify, коммит и пауза с отчётом.
- Перед проектными решениями используй скиллы Superpowers: `brainstorming` (анализ бага с фризами и архитектурные вопросы), `writing-plans` (план рефакторинга), `systematic-debugging` (причины зависаний), `verification-before-completion` (перед заявлением «готово»).
- Не считай задачу выполненной без успешного `pio run`; ручную проверку на железе отмечай отдельно от проверки сборкой.
- Секреты — только в `include/Secrets.h` (в `.gitignore`). В репозиторий попадает лишь `include/Secrets.h.example` с заглушками.
- Коммиты: один блок — один осмысленный коммит (`feat(light): ...`, `fix(floor): ...`, `docs: ...`); пуш после каждого блока по PRD.
- Если требование PRD неоднозначно или расходится с легаси — спроси, зафиксируй ответ и обнови документацию. Открытые вопросы перечислены в конце `AGENTS.md`.
- Перед вопросами об архитектуре читай [`graphify-out/GRAPH_REPORT.md`](graphify-out/GRAPH_REPORT.md); после изменений кода обновляй граф командой `graphify update .` (симлинк в `~/.local/bin/graphify`).
